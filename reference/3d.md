# 3D models

A `model` scene places a glTF/GLB/OBJ/STL/FBX file into the comp as a 3D Model layer. The comp's renderer switches to **Advanced 3D** automatically, and the pipeline adds a key light (Parallel) plus an ambient fill so the geometry reads with shading instead of a flat silhouette.

## Spec fields

| field | type | default | what it does |
|---|---|---|---|
| `src` | string | *required* | Model filename or path. Bare name → `assets/3d/<name>` (`.glb` appended when no extension). Path containing `/` → resolved relative to the spec file. |
| `scale` | number | `55` | Uniform scale percent applied to the layer. A unit-sized model at the default `unitScale` of 480 needs roughly 55 to fill the frame. |
| `spin` | number | `0` | Total Y-axis rotation in degrees across the whole scene. `360` = one full turn, regardless of scene length. |
| `tilt` | number | `-22` | Static X-axis rotation in degrees. Negative tilts the model toward the camera. |
| `position` | `[x, y]` | `[540, 960]` | Layer anchor in comp pixels (1080×1920). Default is frame centre. |
| `light` | number | `100` | Key light intensity (Parallel). The light is added automatically; set to `0` to disable. |
| `fill` | number | `25` | Ambient fill intensity. Raises the shadow side without washing out the key. |

Example:

```json
{
  "type": "model",
  "src": "torus.glb",
  "scale": 55,
  "spin": 360,
  "tilt": -22,
  "position": [540, 960],
  "light": 100,
  "fill": 25
}
```

## Source resolution

- `src: "torus"` or `src: "torus.glb"` → `assets/3d/torus.glb` (shipped primitives).
- `src: "./product.glb"` or `src: "models/hero.glb"` → resolved relative to the spec file.

## Shipped primitives

Five dependency-free GLBs live in `assets/3d/`:

| name | file |
|---|---|
| cube | `assets/3d/cube.glb` |
| sphere | `assets/3d/sphere.glb` |
| torus | `assets/3d/torus.glb` |
| cylinder | `assets/3d/cylinder.glb` |
| plane | `assets/3d/plane.glb` |

Regenerate any of them with the zero-dependency writer:

```sh
node lib/glb.mjs <cube|sphere|torus|cylinder|plane> <out.glb> [--color "#rrggbb"]
```

The colour is baked into the file as `baseColorFactor`.

## Bringing your own model

Any exporter that writes glTF works:

- **Blender** — File ▸ Export ▸ glTF 2.0 Binary (`.glb`).
- **Spline** — Export ▸ glTF/GLB.
- **three.js** — `GLTFExporter` from the examples.
- `.obj`, `.stl`, `.fbx` from any DCC tool.

Practical constraints:

- **Colour lives in the file.** The model layer has no colour property of its own; the material's `baseColorFactor` is what renders. To recolour, re-export with a new `baseColorFactor` (or regenerate a primitive with `--color`).
- **Unit scale.** `geometryOptions/unitScale` defaults to 480, so a model authored at 1 unit needs `scale` around 55 to read at frame scale. Export at a sensible real-world size or tune `scale` per scene.
- **One model switches the comp.** Adding a model layer sets `comp.renderer = "ADBE Advanced 3d"` for the whole comp. Other 2D layers in that comp continue to render; the renderer change is what enables lighting and depth.

## Lighting

The pipeline adds two lights automatically, plus a 0.35 s opacity fade-in on the model (`fade: false` disables it):

- **Key** — Parallel light (`lightType = 4412`), intensity from `light` (default 100).
- **Fill** — Ambient light (`lightType = 4415`), intensity from `fill` (default 25).

Without any light, a 3D model renders as a flat silhouette — the geometry is there but the shading is not. The engine's built-in default ambient keeps the shape visible, so a lit scene reads as a jump in tone count (≈145 vs ≈65 distinct tones on a torus) rather than black versus visible. Raise `light` for harder shadows, raise `fill` to lift the dark side. Set `light: 0` only when you want the silhouette look on purpose.

## When to prefer this over baking

Use `model` when the geometry must read as 3D and stay editable — spin, tilt, relight, rescale — all from the spec.

Bake to footage (a PNG sequence imported with `file.import`) when the look needs something the engine has no equivalent for: custom shaders, volumetrics, three.js post-processing, or a hyperframes composition. Bake once, import the frames, treat them as a 2D layer.
